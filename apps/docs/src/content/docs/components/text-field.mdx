`<cosm-text-field>` is a labeled, single-line text-entry control. Use it for text, email, password,
telephone, URL and search input. It supports browser constraints and web form association; use a
separate number field or textarea for numeric or multiline editing.

## Playground

Use the dropdowns for type, variant, size, keyboard hint and a few sample icons, and the checkboxes
for boolean features. Less common form, content and action-label settings are under **Advanced
options**; the complete API remains below. The icon catalog is available on the Icon page rather
than loaded into this playground.

For digit entry, choose `text` and `inputMode="numeric"`; this requests a numeric keyboard, not
numeric validation or filtering. Use web `pattern` or consumer-owned validation when appropriate.

## Variants

`outlined` is the default. `filled` changes only the control surface; semantic sizes are `sm`, `md`
and `lg`. A positive finite numeric `size` sets a minimum editable-control height in CSS pixels.
Label and supporting text remain outside that height.

## States

Help and external error text are associated with the input. `required`, `type`, `pattern`,
`minLength` and `maxLength` use browser-native validity on web. A custom error or `invalid` state is
consumer-owned and is not inferred from business rules.

  <cosm-text-field label="Invalid account" value="taken" error="That name is unavailable." invalid></cosm-text-field>
  <cosm-text-field
    label="Password"
    type="password"
    password-reveal
    reveal-password-label="Show password"
    hide-password-label="Hide password"
    value="sample secret"

  <cosm-text-field label="Read-only" value="Cannot edit" read-only></cosm-text-field>
  <cosm-text-field label="Disabled" value="Unavailable" disabled></cosm-text-field>

Structured `startIcon` and `endIcon` values are consumer-provided `IconDefinition`s; there is no
global icon-name registry. Select icons in the playground, or pass the definition as a property.
Clear and password-reveal actions use local native buttons. Supply localized `clearLabel`, and both
`revealPasswordLabel` and `hidePasswordLabel`, whenever those actions are enabled. Actions are
hidden while disabled or read-only.

On web, the custom element is form-associated: it submits `name` and `value`, follows disabled
fieldsets, supports reset/state restoration, and exposes browser-native validity. An autonomous
reset returns to `defaultValue`; a controlled reset emits a proposal and waits for its owner.
Angular integrates with `ControlValueAccessor`, including touched state, reset, disabled state and
`updateOn: 'blur'`. Native does not emulate HTML form submission, email validation or regex
validation; its consumer owns business validation and submit handling.

## Accessibility

- Always provide a meaningful `label`. `labelHidden` visually hides it without removing its
  association with the editable input.
- Placeholder text is only a hint, never a label. Help and error text use `aria-describedby`, and
  invalid/required states are exposed on the input.
- Clear/reveal controls have localized accessible names, visible focus indication and native button
  keyboard behavior. They are unavailable in disabled or read-only states.
- The editable input remains keyboard-operable; Enter reports `cosm-submit` and web form submission
  continues through the containing form.
- Decorations follow logical inline direction for RTL. Font scaling may grow the control beyond a
  custom minimum height; content is not clipped.
- React Native 0.88 exposes no native accessibility states for required or invalid. On native,
  include localized required wording in the existing label or help text and provide explicit error
  text for invalid fields. Hints may be disabled; error text is readable and is an Android live
  region, but TalkBack/VoiceOver behavior is not verified here. Do not assume semantic parity across
  devices.

## Events by platform

`cosm-change` proposes `{ value }` for each edit or clear. An unbound field commits autonomously;
when `value` is bound (including `''`), the owner accepts the proposal by updating the property.
Rejected proposals restore the controlled text without discarding the caret or an active IME
composition. Password reveal changes presentation only.

`cosm-submit` reports `{ value }` when Enter invokes the submit action. React and Angular receive the
original bubbling, composed `CustomEvent`; React Native receives the detail through its callback.
