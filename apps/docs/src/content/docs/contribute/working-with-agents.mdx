The repository ships a team of specialized agents (`.github/agents/`) and step-by-step skills
(`.github/skills/`, each with a prompt in `.github/prompts/`). They follow `AGENTS.md`, the rules in
`.github/instructions/` and the [component anatomy](https://github.com/joralvmel/cosmos-ui/blob/develop/docs/conventions/component-anatomy.md).

## How to use them in VS Code

1. Open the repository in VS Code with GitHub Copilot and open the **Chat** view.
2. **Agents**: pick one in the agent selector of the chat (for example `component-builder`), then
   describe the task. The agent loads its rules and uses its skills.
3. **Prompts**: type `/` and the skill name, e.g. `/create-component`, `/component-status`,
   `/start-work`. The prompt asks for its inputs and runs the skill with the right agent.
4. Attach context with `#` (a file, a folder or a Figma link) when it helps.

Other assistants (Codex, Claude Code, Cursor…) read `AGENTS.md`; point them to a skill file, e.g.
"follow `.github/skills/create-component/SKILL.md` for `switch`".

## Research, decisions and local review

Follow the [component workflow](https://github.com/joralvmel/cosmos-ui/blob/develop/docs/conventions/component-workflow.md).
The main chat coordinates specialists and keeps the conversation with you:

1. The researcher compares standards and public implementations, with licenses, platform
   differences and costs. Its recommendation is not permission to implement everything.
2. Copilot presents required, recommended and optional features, then asks small batches of
   design/API questions. You approve what is included, excluded or deferred **before generation
   or contract edits**. Examples do not silently become special cases or exclusive feature lists.
3. Agents implement the accepted scope and run checks themselves. The evidence report distinguishes
   actual browser/wrapper checks, React Native Web, mocked tests, builds and Android/iOS runtime.
   Unavailable tools, devices and screen-reader checks must be reported, not marked passed.
4. `finish-work` validates and automatically creates a **local commit**, reports its SHA and how
   to try it, then **waits without push or PR**. Request changes for another commit and review
   pause, or accept that exact commit to authorize `open-pr` to push and create/reuse the PR.

An initial request to implement and eventually open a PR is not approval of unseen changes.
Approving the feature scope is different from accepting the implementation. A changed HEAD needs
another review; agents do not amend earlier commits by default.

The test and native agents include browser tools, and coordinating roles can delegate and ask
interactive questions. Availability still depends on your harness and enabled tools. The workflow
does not bypass editor permissions or add a new GitHub approval requirement.

## What to ask

- **One task at a time**, with the outcome you expect: "Create the `switch` component for all
  platforms" rather than "work on forms".
- **Give references**: an issue number, a Figma link, a pattern of the WAI-ARIA APG.
- **Let them validate**: implementation work includes tests and
  `npx biome ci . && npx turbo run typecheck test build`. Research-only work returns sources, not
  invented test results. Ask for the evidence and unavailable checks.
- **Review before merging**: ask `reviewer` for a review of the branch.

## Copyable prompts

```text
/component-status all — and tell me which three components I should build next and why.
```

```text
/start-work feat elements switch, linked to issue #12
```

```text
Create "switch" for web, React, Angular and React Native using create-component. Research first,
then recommend its features and ask me about scope, design, customization and platform differences.
Wait for my scope approval before generation or contract edits. Implement and test the agreement,
commit locally and let me validate it before any push or PR. If I request changes, make a new commit
and wait again.
```

```text
/component-from-design https://www.figma.com/design/<file>?node-id=<node> as "chip"
```

```text
Use the design-system agent: add a theme called "aurora" with a teal primary and a triadic harmony;
it must pass the accessibility validation in light and dark.
```

```text
Use the reviewer agent: review the current branch against develop and list only high-confidence
problems.
```

```text
/finish-work "feat(elements): add cosm-switch" closes #12
```

This creates the local review commit and pauses. After trying that commit, reply:

```text
I approve the reviewed commit <SHA>. Push it and open the PR to develop.
```

Or request another iteration:

```text
Adjust the disabled appearance and its tests. Make a new commit and wait for me to validate it;
do not push yet.
```
